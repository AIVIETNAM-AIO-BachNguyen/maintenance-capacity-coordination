# Fixed-threshold requester / learned-coordinator diagnostic v1

Status: LOCKED BEFORE DIAGNOSTIC OUTCOMES, 2026-10-22 (Asia/Taipei). This is a single attribution follow-up to coordination pilot v1, not a revision of its primary protocol, analysis, or sealed TEST gate. It is motivated by the audited result that C beat always-request D but not local requester B, centralized E, frozen V14, or strong rules. It does not make the post hoc diagnostic confirmatory.

## Question and prediction

Does fixing PM submissions to the inherited threshold while learning the coordinator close the finite-budget cost gap between C and D? Arm G has the threshold requester and the exact same masked coordinator and centralized critic architecture, PPO settings and sample budget as D. G never learns request timing. If G cost is at least as low as C for both cases and all three paired training seeds, the C–D gap is plausibly explained by request gating rather than learned capacity-aware requester decisions. If G remains near D while C is lower, learned timing remains a plausible finite-budget contributor. Otherwise the diagnostic is inconclusive. No structural requester-necessity claim follows.
