## Native Windows work remains separate

This publication supplies the missing source; it does not certify native
Windows support. The existing lab runners import Unix-only `resource`, some
older engineering collectors use `SIGALRM`, and the L3 concurrent-lab launch
guard checks `tmux`. Do not launch these scientific commands unchanged on
Windows or remove guards to force them to run.

Prepare a new versioned Windows entry point and compatibility helpers. Keep
the frozen simulator, actors, PPO, and historical runner bytes unchanged.
Preserve resource/time caps using Windows-supported measurements with explicit
units and metric definitions. Verify Python 3.12 x64 and the locked package
versions; do not silently substitute a different Torch release.

Windows setup is complete only after focused tests, bounded fresh-seed
engineering train/save/load/evaluation, and independent replay pass on the
actual Windows host. Setup does not authorize a scientific campaign or reuse
of L2/L3 seeds. Fresh source hashes and environment details must be recorded.

To update an existing Windows checkout, first inspect `git status --short` and
preserve local setup work. On `main`, use `git pull --ff-only origin main` only
when local changes will not be overwritten. If the checkout has local commits
or conflicting untracked files, inspect and reconcile them without hard reset,
clean, or deletion. No `.venv` is portable between operating systems.

On Linux/macOS, engineering validation uses:

```sh
uv sync --locked --extra dev
uv run --no-sync pytest -q tests/test_component_service_v1.py tests/test_jcst_*.py
uv run --no-sync python experiments/jcst_learnability_l2.py --stage smoke
uv run --no-sync python experiments/jcst_learnability_audit_l2.py NEW_SMOKE_DIR
```

The shell glob and Unix runner commands above are not native PowerShell setup
commands. `NEW_SMOKE_DIR` must be the new directory printed by that smoke.
Engineering artifacts are not scientific evidence.
