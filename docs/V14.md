# Self-contained V14 baseline and reproduction

This package is a frozen baseline, not the new framework objective. Historical V14 failed its identity-specific mechanism gate; importing it does not change that result.

## What is included

- Ten selected trained actors: competition and count-calibrated, training seeds 72600000–72600004; about 194 KB total checkpoint bytes.
- Original selection, summary, seed registry, protocol, proposal and configuration under baselines/v14.
- Complete original counterfactual-Q/KL trainer and its eleven-module dependency closure under legacy/v14/src. No new V14 optimizer was invented for this migration.
- Original V14 capacity-control tests, all historical seed registries from the training revision, and the later seed-corrected independent verifier.
- Full original V14 run including every iteration checkpoint/Q bank, the V7 comparator run, and the historical independent audit. These are both unpacked locally and contained in baselines/v14/reproduction_bundle.tar.gz so a new clone need not access the old project or lab.
- Source and asset hashes in provenance/v14_extension_manifest.json. Source inputs match the original V14 run manifest.

The original training revision is 3abbf14559b48c3b461fe04c53f722d5d4967f6c. The eleven runtime modules remain byte-preserved; only package initialization is narrowed to avoid importing unrelated FJSP modules. The verifier comes from 2343d79d70d1c1fc2f857da2a5afe35c4d501527, which includes the disclosed verifier seed correction. Original paths inside old manifests/reports are historical labels, not runtime dependencies on the old checkout.

The top-level V14 adapter preserves the original masked-softmax/NumPy-argmax decision rule, including float32 near-tie behavior. Replacing it with raw-logit argmax can change historical actions and is not treated as an equivalent deployment.

## Commands from the new repository

```bash
uv sync --frozen --extra dev
uv run mcc-v14 evaluate
uv run mcc-v14 training-smoke
uv run mcc-v14 tests
uv run mcc-v14 audit
```

- `evaluate`: replays all selected actors on the already-opened original 16-seed DEV panel; reports every metric mismatch against the original Ubuntu CSV without overwriting it. Operation COMPLETED means replay finished, not historical equality. It is not fresh confirmation.
- `training-smoke`: one original smoke update for both arms, including on-policy collection, common-scenario root Q, original optimizer update, save/load and deployment checks. It does not reproduce the full six-update research result.
- `tests`: original V14 capacity/control tests in the isolated runtime.
- `audit`: runs the corrected original verifier against the full original V14 run, with new output under artifacts. This recalculates source, Q-bank samples, selected episodes and summary gates; it does not retrain the actors.
- `restore`: checks the portable bundle hash, then restores missing historical files without overwriting any existing file. Other commands requiring historical run files do this automatically.

Each operation creates a fresh timestamped artifact directory. No command contacts the old repository or SSH host. Direct `V14Controller` usage runs with the top-level simulator; reproduction commands execute in a subprocess with only the legacy source directory added ahead of installed packages. The original V14 DEV panel is already opened and must never be reused as fresh TEST.

For exact original campaign execution after this new repo has its own committed source, use `uv run mcc-v14 campaign --profile smoke`. `--profile dev` remains subject to the original committed-source guard, old seed definitions, current authorization and research workflow. It is a historical reproduction, not an eligible new framework experiment. Do not launch it as part of setup or silently reuse its panels for new TEST.

## Current macOS replay limitation

Exact Ubuntu episode metrics do not all reproduce on the current Apple Silicon environment, even in the byte-preserved original runtime. The unchanged verifier passed its 240 selected source/Q-bank replays, then failed during selected-policy episode replay. This migration does not label that full audit PASS. The original Ubuntu audit remains archived with its original scope; it is not a new Mac audit.

The top-level deployment adapter is tested against the isolated original runtime on this same host. Separate historical replay records every mismatch. Backend/float32 near-tie sensitivity is a possible cause, not established by these checks; no inference rule, weights or reference CSV is changed to force historical agreement. Recheck the unchanged verifier on the intended Ubuntu environment before using historical cost values as reproduced measurements.
