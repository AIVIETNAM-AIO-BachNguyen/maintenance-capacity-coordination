# V16 dynamic bipartite demand–capacity encoder: locked pilot

Status: design/protocol locked before v16 implementation, engineering smoke, train/DEV or held-out outcomes. V15 is closed no-go; all older gates remain final. Simulator trajectories and the fixed audited v15 *training-label* bank are the only learning data. No new TEST is authorized.

## Independent hypothesis and prior boundary

V15's actor-path audit established that C/D/B/P cannot use positive technician busy-time magnitudes even though they occur in raw tensors, and that its machine embeddings are computed once per tick. On actual simulator label states, equal residual edge counts sometimes have different maximum matching capacity. The v16 hypothesis is that a small, incidence-aware, **recomputed** demand–capacity representation can make conditional matching decisions more economically useful than (i) the same graph representation frozen at the root, (ii) all-entity information without graph message passing, and (iii) the v15 feasible-edge encoder, under matched simulation data and physical actions. This is an empirical question, not a claim of novelty from sequential decoding or GNN use. Xu et al.'s multiset result, AirME/HetGPO, Song et al. and DANIEL are the specific primary precedents summarized in `representation_path_audit_v15.md`; none establishes a maintenance H+tail gain here.

## Operating contract and architecture

Use the two already fixed `n5k3_residual_a/b` configurations from v12/v15 (config seeds 74740000/74740001, N5/K3, H48+tail16), threshold PM submissions, automatic CM, unchanged failure/service/restoration/cost law and all 136 legal physical matchings including WAIT. Within each tick, construct a unique increasing-edge sequence with STOP; selected edges are **provisional** until the final matching is executed once. No future tape, fee, reward shaping, time advance, repair or cost occurs between decoder tokens. All arms see the same present-state tensors and legal physical action set under threshold admission, except Q16's declared always-request admission reference. The old N4/K2 V14 cannot act on N5/K3 and is historical external context, not a same-panel control.

For graph arm C16, encode every machine and technician from the existing v15 tensors, including unrequested machines and busy technicians. Every present-state *compatible* pair (`service_time>0`) is a graph edge with service duration/restoration attributes; eligibility for immediate assignment is a separate action mask. A single bipartite pass computes machine→technician messages, sums them by technician, updates technician vectors, then computes technician→machine messages, sums them by machine and updates machine vectors. Messages include the endpoint encodings, duration/restoration, queued/selected flags and worker availability. A selected technician's **provisional** release estimate is the selected pair's known service duration; an already busy technician retains its observed remaining time. The estimate is a planning feature, not a physical reservation. Recompute this pass after every provisional selection. Score each feasible candidate using its refreshed endpoint vectors, selected-edge sum, candidate-specific residual mean/max/count and a pooled all-machine/all-technician context; STOP uses the current analogous context. Keep one pass (two directed stages), sum aggregation and no attention or auxiliary new loss fixed through the pilot.

D16 has **exactly the same modules, parameters, input and initial logits** as C16, but caches root endpoint/edge/context scores while updating canonical feasibility only. CF16 loads each DEV-selected C16 state dict into D16 at evaluation, isolating same-weight inference-time feedback. I16 receives all machines/technicians, including positive busy time and unrequested-machine features, through shared node encoders and a global pooled context, plus the same candidate-residual summaries; it has no incidence-aware message passing. R16 is a freshly trained v15 feasible-edge C architecture; B16 is the direct-feature sequential control. S16 is the structured complete-matching control, G16 flat full-information complete-matching control, Q16 always-request flat control and P16 graph PPO-only control. C/D/I/R/B/S/G receive the same fixed listwise conditional-value labels and fixed 64-epoch pretraining; P/Q receive no labels. Report active parameter count, label/pretraining/PPO compute, scorer/decoder forward passes, forecast transitions and wall time. C−I tests the relation-aware encoder **in addition to** complete input access; its parameter/compute differences must be reported, so that contrast alone is not a pure causal attribution. C−D and C−CF are the feedback attribution tests.

PPO uses the v15 canonical sequence formulation for C/D/I/R/B/P: one valid sequence per physical matching, log probability sums exact token conditionals and the physical return is attached once to the final matching. Sampled conditional entropy sums are path statistics, not full matching entropy; deterministic tokenwise greedy need not return the highest-probability matching. S/G/Q use a single masked categorical over complete physical matchings. Preserve v15 gamma .99, GAE .95, clip .2, entropy .01, 256-step rollout, minibatch64, four PPO epochs, Adam 3e-4, gradient clip .5, one CPU Torch thread and 8,192 H decisions per case/arm/root. Pretraining has 64 epochs, batch64, Adam 3e-4, no label-based checkpoint selection and a fresh PPO optimizer. The label bank is `artifacts/conditional_value_v15_labels_20261023T032931104204Z`: label manifest SHA-256 `0c0461473b3dd4ef9a9725e2380b6da997573f231ecba4f37ff90648b07a072f`, audit SHA-256 `7fc90159181659312fb8300f44fca25a2bc1f78d3ad73566ff31f1018a248889`, labels SHA-256 `5de1201214c3860c2f9c13a22f87e7730be1069a4321b00fd3c898d1349de94e`. Its 457 selected states and 3,832 branches are training data, not new DEV/held-out evidence. Future tape and target costs never enter inference.
