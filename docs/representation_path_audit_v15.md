# Representation-path audit after v15

Status: source and training-label-bank diagnostic, **not a new scientific performance experiment**. The label bank is simulator-generated and independently replay-audited. All v15 held-out outcomes and its no-go gate remain as recorded in `conditional_value_pretraining_v15_findings.md`; this note does not select checkpoints, alter the protocol, or open TEST.

## Prior work read and scope

1. Xu, Hu, Leskovec and Jegelka, *How Powerful are Graph Neural Networks?*, ICLR 2019, arXiv:1810.00826v3, Sections 4–5. Mean and max can collapse distinct neighbor multisets; sum with an appropriate transform can preserve bounded, countable multisets. This theorem does **not** prove that our mean/max/count plus candidate-conditioned MLP loses a particular real simulator state, nor that a GNN would improve economic cost.
2. Z. Wang and Gombolay, *Stochastic Resource Optimization over Heterogeneous Graph Neural Networks for Failure-Predictive Maintenance Scheduling*, ICAPS 2022, pp. 527–536, especially pp. 530–531. AirME recursively updates a heterogeneous graph between proposed maintenance decisions and only then executes the collection. It also uses a state node and decision nodes. Its paper simplifies its AirME decision graph for **homogeneous crews**, so our heterogeneous technician compatibility and service times require explicit edges; sequential assignment and STOP are prior art.
3. Song, Chen, Li and Cao, *Flexible Job Shop Scheduling via Graph Neural Network and Deep Reinforcement Learning*, IEEE TII 2022, DOI 10.1109/TII.2022.3189725, Sections III–IV. Compatible operation–machine edges carry processing time; assigning an operation changes graph edges, then machine embeddings aggregate eligible operations and operation embeddings aggregate their machine alternatives. The FJSP makespan objective and physical decision timing differ from this maintenance simulator.
4. R. Wang et al., *Flexible Job Shop Scheduling via Dual Attention Network Based Reinforcement Learning*, arXiv:2305.05119v2, Sections III-B/C. DANIEL recomputes a reduced relevant state and uses pair features, remaining process/free time, and a machine-competition message built from shared eligible operations. Its competitive relation is a concrete analogy for technicians sharing maintenance requests. Attention uses a weighted average; multiplicity still needs care. Its FJSP results are not evidence for our H+tail objective.

## What C15 actually receives and retains

The raw `actor_inputs_scaled` tensors contain all machines, all technicians, service times/restoration and each technician's remaining busy time (`scaled_coordination_v11.py`). The global critic input also contains remaining times. But `ContextActor.encode` (`same_tick_policy_v15.py`) constructs each edge independently from one machine, one technician, duration and restoration. `_path` calls it **once at the start of the tick**. `logits` subsequently changes feasibility/selected masks and selected-edge plus candidate-residual pooled context, while reusing the same machine, technician and edge embeddings. This makes second-step edge scores dynamic, so the actor is not literally frozen; the machine-specific demand vector itself is not recomputed for the remaining technician set.

For a feasible edge `(m,j)`, `eligible_edges` requires technician `j` to be idle, hence the technician's remaining-time input is zero. Since `j` can service `m`, machine feature `min(remaining of compatible technicians)` is also zero. Busy technicians' edge embeddings are computed but removed from every current and candidate residual pool by the feasibility mask. Machines already under service or with no queued request also contribute no feasible edge. Therefore, while feasibility stays fixed, C15/D15/B15/P15 actor logits are **invariant to the positive remaining-time magnitudes** of busy technicians. The actor can infer *which* workers are unavailable from the mask and static per-machine skill columns, but not whether a busy worker returns in one or three ticks. S15 pools all worker embeddings and G15 receives a flat all-entity tensor, so those controls have a path for that numeric signal. Raw input parity is not effective information-path parity.

Checks without training or raw-result edits:

- In the 457 audited label states, 233 have at least one busy technician and still have an eligible immediate edge (108/268 in case a, 125/189 in case b). Across all 2,406 feasible edges, the selected worker's remaining-time and that machine's minimum-compatible remaining-time features were zero. These frequencies are **conditional on v15 label-state selection**, not population prevalence or a performance estimate.
- Using the real C15 checkpoint `n5k3_residual_a_C15_77710000/checkpoint_8192.pt` and label state raw seed 77701001 at tick 9, changing busy technician 0's remaining input from 2 to 4 ticks changed no logit (`max |Δ| = 0`). The same perturbation yielded 0 for D15/B15 and nonzero differences for S15/G15 (maximum unmasked actor-output changes 0.00763/0.00490 for those checkpoints). This verifies the code path, not an economic effect.
- 448/457 selected label states have an unrequested machine whose features cannot enter C15's feasible-edge pool. In a real label state, perturbing one such machine's age while holding admission/mask fixed also changed no C15 logit. Whether the policy needs that particular future-demand information for H+tail decisions is untested.

## Structural substitution and partial matching

`residual_summaries` returns feasible-edge mean, componentwise max and count, including a candidate-specific summary after each possible edge. The candidate-specific **count does reveal immediate edge loss**; therefore the simple claim that a three-edge star and a flexible three-edge graph are necessarily indistinguishable to the *whole policy* is too strong. The per-edge embeddings also include each machine's full service-time and compatibility columns. Still, the summary has no explicit per-machine or per-technician neighbor aggregation or residual matching capacity.

On the audited label bank, after the preselected first edge, case a contains 18 states with exactly three remaining eligible higher-index edges: eight permit at most one more assignment, ten permit two. For example, raw seed 77701006 at tick 13 has residual edges `(1,2),(2,2),(3,2)` (capacity one); seed 77701017 at tick 33 has `(3,2),(4,1),(4,2)` (capacity two). Thus **edge count alone** conflates attainable matching size in actual reachable states. Their learned mean/max vectors need not coincide; we have not established an actual collision or failure to decode capacity. A constant-edge-embedding construction gives identical mean/max/count for a one-worker star versus a two-worker split but is an architecture counterexample, not a sampled physical state.

Because `_path` encodes once, a machine's own embedding does not update after another provisional assignment takes away its only feasible worker. The feasibility mask correctly prevents impossible assignments; candidate-conditioned context may still communicate part of the loss globally. What remains unverified is whether this indirect route can preserve the *specific* machine–worker substitution, urgency and future-availability interactions needed to choose a lower-cost matching.

## Focused successor design to prelock separately

A minimal testable successor is a **dynamic bipartite demand–capacity encoder** over all present-state compatible machine–technician edges, including busy technicians as future capacity. Edge messages would carry service duration, restoration, queued/ready status and technician remaining time. A technician receives a sum of messages from compatible machines, preserving competition/multiplicity; each machine then receives messages from its compatible technicians. The messages and each machine's representation are recomputed after every provisional pair with selected-machine/worker flags and predicted service commitment, without advancing simulator time or cost. Candidate logits use the updated endpoint vectors and a small global readout. A second message round may be needed for a machine to see other machines competing for its technicians; lock depth before outcomes. This is an adaptation of known graph-policy mechanisms, not novelty from merely using a GNN/attention.

To separate missing information from lost relation, a new prelock should compare: existing feasible-edge actor; an **all-entity input-path repair** with comparable pooled context but no incidence-aware messages; dynamic bipartite messages; a same-weight frozen-message ablation that still updates legality; and full-information complete-action and strong rollout controls. Hold the physical action set, admission, H+tail simulator and PPO/label budgets fixed. Diagnostic unit tests should verify busy-time and nonrequested-risk sensitivity, distinguish same-count capacity-one/two motifs, and keep matching/kernel equivalence. Those are engineering checks, not performance proof. A qualified pilot then needs fresh simulated train/DEV/held-out physical seeds, predeclared economic C−frozen and graph−input-repair contrasts, clustered intervals, compute accounting, independent audits, and a practical gain gate. No TEST is authorized. Real logs and public FJSP benchmarks are unnecessary for simulator RL training; they could only serve later calibration or out-of-domain evaluation.
