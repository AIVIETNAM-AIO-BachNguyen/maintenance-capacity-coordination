# V2 bounded headroom check — prelocked protocol

Status: LOCKED BEFORE V2 DIAGNOSTIC OUTCOMES, 2026-10-22 (Asia/Taipei). This is one bounded decision check, not a training or scientific TEST campaign. The v1 TEST is closed to all design selection.

## Question, estimand and scope

On states visited by the strong threshold + six-tick/16-scenario rollout F2, can allowing immediate PM service of an otherwise unrequested healthy machine lower short-horizon economic cost? Compare F2's threshold-admitted root matching with a root selected from the superset that includes those extra PM candidates. Both choose using the **same** 16-model-scenario forecast bank and the same six-tick threshold + risk-matching continuation. Evaluate both fixed choices on an independent common 32-scenario holdout bank. Primary estimand: mean paired holdout difference, expanded minus F2, averaged over sampled H states and then equally over physical episodes and the two cases. Lower is better. The check establishes only finite-horizon model-based headroom on the sampled F2 state distribution. It does not show that an RL policy learns it, that this is an optimal policy, or that H+tail episode cost improves.

## Frozen operating contract and sampled states

Use the unchanged `shared_maintenance_requests_v1` transition and `pending_matching_completion_v1` physics for `reciprocal_scale2` and `specialist_generalist_scale2`, H=48, with no modified costs, failure law, skills, restoration or event tapes. Generate 16 F2 episodes per case on new raw physical seeds 73170000–73170015, using the same `maintenance_framework_v1:physical` derivation as prior panels. At exactly ticks 0, 6, 12, 18, 24, 30, 36 and 42 of each episode, before F2 acts, record the current state and compare actions. The other H ticks only advance the F2 trajectory. No state is selected for favorable outcomes. The old DEV, held-out physical and sealed TEST roles and the G diagnostic raw and derived seeds must be disjoint from these new roles.

For each selected state, admit ordinary threshold PM submissions first. Enumerate all feasible partial matchings, including WAIT, after also provisionally admitting every healthy, operating, unoccupied machine without a request. This enumeration does not mutate the real trajectory. A candidate matching that includes such a machine submits its PM request immediately before service; unchosen extra machines create no request. Existing queued PM/CM requests and threshold submissions follow the unchanged lifecycle. F2 chooses among the threshold-only legal subset using its original role-derived forecast bank, 16 scenarios and depth `min(6, remaining physical horizon)`. Score only expanded extra roots on exactly that same bank; initialize the expanded winner to F2's choice and retain F2 on ties. Under the resulting winner, submit only the selected extra PM candidates. All scoring uses the same root transition and threshold + risk-matching continuation; no realized episode event tape enters action selection.

Use a separate independent 32-scenario holdout bank per case/raw seed/tick, derived from role seed base 73171000 with label `commitment_headroom_v2:holdout:<case>:<seed>:<tick>`. Score the frozen F2 and expanded choices on this common bank. Report per-state root counts, whether an extra PM was chosen, selection-bank and holdout costs, paired difference, forecast transition counts and runtime. All episodes and sampled states remain in the output, including no-extra-action and zero-difference states.

## Analysis and gate

Average the eight tick differences within each physical episode. Equal-weight the 16 episodes within each case and the two cases. Use 5,000 paired bootstrap draws with analysis seed 73172000, resampling physical episodes **as clusters within each case**; all eight overlapping windows from an episode stay together. Report each case mean, overall mean, 95% cluster interval, percent of sampled states where an extra PM is selected, and forecast transitions. Do not treat overlapping states or the 32 holdout scenarios as independent episodes. The go gate for a learning pilot requires: overall expanded-minus-F2 holdout mean at most −2.0 economic units per six-tick decision; 95% cluster interval upper endpoint below zero; both case means below zero; and an extra PM selected on at least 5% of sampled states. Otherwise conclude this action-set change has insufficient demonstrated headroom and do not open a v2 learning pilot. Never relax this gate after seeing outcomes.
