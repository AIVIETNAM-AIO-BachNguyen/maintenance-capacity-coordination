# Demand and technician-commitment coordination: v2 proposal

Status: design proposal, 2026-10-22 (Asia/Taipei). This does not revise pilot v1, its sealed TEST, or the exploratory G diagnostic. The sole current experiment is the bounded headroom check in `commitment_headroom_v2.md`; no v2 learning campaign is open yet.

## What pilot v1 established

The operating problem is the cost of serving a machine now versus leaving it productive and exposed to failure, while a heterogeneous technician becomes occupied for several ticks. Pilot v1's learned requester action mainly opened a free PM request that the fully informed coordinator could ignore. C's TEST cost was lower than learned always-request D, but it did not robustly beat local B, centralized E, V14, risk matching, or rollout. Under the pilot budget, B/C under-requested while D over-served PM. The later, separate G diagnostic showed fixed threshold requests plus a learned coordinator outperforming C on its own panel. This is evidence about the v1 formulation and finite-budget optimization, not proof that capacity feedback, a machine representation, or PPO is intrinsically useless. V1 “replication” evaluated previously trained checkpoints on new physical seeds; it was held-out evaluation, not independent training replication.

## Operational decision and minimal mechanism

A shared machine encoder will represent current machine condition and the possible cost/service tradeoff for that machine. A technician encoder will represent current assignments, remaining busy time, skills, service duration and restoration. A coordinator will combine those representations to score complete feasible partial matchings, including WAIT, and the actual matching will be the sole learned physical decision. The machine output is a learned feature vector, **not** a calibrated economic value, urgency, price, or independent machine policy. This is a structured centralized coordination framework; PPO and a centralized critic may be standard. The coordinator retains full current health and resource information, and neither actor nor critic sees realized future event tapes. The proposed structural claim is that sharing a machine encoder and explicitly combining its output with technician commitments can improve learning at a finite sample budget. A direct-health, full-information PPO with the same physical action set and data budget can falsify it.

V2 uses the existing request simulator with a versioned decision adapter. At each H tick, the inherited fixed threshold submits its ordinary free persistent PM requests. The coordinator's candidate catalogue additionally includes any operating, unoccupied healthy machine with no request. If the chosen matching serves one of those extra candidates, the adapter submits a PM request for it **in that same tick**, then starts service. An unchosen extra candidate creates no request. Existing queued PM/CM requests persist, failed machines receive automatic CM, and service remains non-preemptive. The unchanged simulator executes the physical transition and costs; no fee, shutdown, health concealment or future tape is introduced. This changes the H decision contract by widening the set of possible immediate PM service starts, so any v2-v1 or v2-G difference mixes action-set and architecture effects unless controlled. The common 16-tick threshold/risk-matching tail remains fixed. Tests must show that choosing only matchings already legal under threshold admission exactly reproduces the old transition, metrics and event tape.

Threshold + learned coordinator G and always-request + learned coordinator D remain essential named controls, but their request histories and available action sets differ. Primary architecture attribution must instead use newly trained same-action, same-information controls: (i) full-information direct-health PPO without the demand/commitment factorization, and (ii) the same structured encoder with capacity/commitment context removed while retaining model size and action mask. Frozen V14, risk matching and finite-horizon rollout are strong external controls with disclosed training or forecast budgets. Any ablation that also changes the action set will be labelled compound, not evidence for one module. The matching decoder and baselines are limited to the existing two N4/K2 cases until evidence and implementation justify scaling.

## Falsifiable sequence

H1 asks whether widening immediate PM eligibility leaves meaningful decision headroom after the strong six-tick rollout. The single bounded, paired-state, paired-forecast check compares the rollout choice against the best expanded-catalogue choice using identical selection scenarios and independent holdout scenarios. Its estimates are finite-horizon model forecasts, not an optimum or realized H+tail improvement. If the prelocked headroom gate fails, do not launch a learning pilot on this formulation.

If H1 passes, prelock one small v2 pilot before training. H2 compares structured coordination against same-action, full-information direct-health PPO at matched H transitions, with per-case and per-training-seed cost, learning area and runtime. H3 removes capacity/commitment context while preserving the action set, parameter budget and training protocol. G/D and frozen V14/risk/rollout are contextual strong controls; report action-set and compute differences. Independent training replication must train fresh models from new training seeds; evaluating fixed checkpoints on another physical panel is only held-out evaluation. A new TEST remains sealed until a written eligible result and separate user authorization. Neither v1 TEST nor its seed roles may select the v2 design.
