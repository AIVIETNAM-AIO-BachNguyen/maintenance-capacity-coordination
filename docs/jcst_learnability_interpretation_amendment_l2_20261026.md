# L2 pre-outcome interpretation clarification

Recorded 2026-10-26 02:23 UTC, while the first TRAIN trajectory was running and before any L2 DEV evaluation or scientific outcome was inspected. The frozen source/protocol hashes and all numerical selection, confidence-interval and confirmation gates remain unchanged.

The L2 protocol selects one checkpoint and deployment mode **separately per arm and case** from the same four-checkpoint, two-mode opportunity set. Consequently, a selected-bundle S−F or S−A contrast can include different realized training sample counts or deployment modes. It is a fair comparison of equally offered *selection procedures*, but it is not by itself a pure fixed-budget actor-representation or cross-message estimate if the selected checkpoint or mode differs.

The report will always show S/F/A at each matched-sample checkpoint and matched deployment mode on the paired DEV panel. A later representation/mechanism interpretation from selected confirmation requires that the compared arms have the same selected checkpoint **and** same selected deployment mode in that case. If either differs, the corresponding numerical gate is still reported exactly as prelocked, but the conclusion is labelled a selected-recipe contrast; no pure architecture/mechanism support is claimed from it. No arm is reselected, retrained or reevaluated to force matching after outcomes.

This clarification narrows claims and does not manufacture a pass. It also preserves the primary question here: whether the unchanged PPO recipe learns useful economic behavior as budget increases, including whether stochastic deployment resolves a greedy WAIT artifact.
