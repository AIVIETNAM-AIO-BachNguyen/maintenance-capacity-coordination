# Structured demand–commitment coordination: v3 proposal

Status: new formulation proposal, 2026-10-22 (Asia/Taipei). The v2 early-PM action-set expansion failed its prelocked headroom gate and remains closed. V3 does not revise that result or pilot v1 TEST. It tests a different claim: whether explicit machine/technician factorization helps *learn* feasible service commitments at a finite budget under the inherited threshold-request operating contract.

## Operational decision and prior controls

Every H tick, a fixed threshold creates ordinary free persistent PM requests; failures create CM automatically. The coordinator selects a feasible partial matching or WAIT. A service start trades current downtime and technician occupation lasting 2–8 ticks against future failure and production loss. The same worker can be fast on one machine and slow or incompatible on another. G already showed that fixed threshold plus a learned coordinator is a strong finite-budget control, while F2's six-tick model rollout is a stronger cost reference with much greater forecast compute. Pilot v1's binary requester mostly gated free eligibility and did not establish a capacity-feedback gain. V2's added early-PM choices created only a small six-tick model-forecast gain, so they are excluded here. No v3 action enlarges, suppresses or changes the request set.

## Proposed representation and causal path

A single shared encoder maps each machine's current age, failure/request/service state, skill edges, service durations, restoration and cost constants to a demand feature vector. A shared worker encoder maps each technician's free/busy state, remaining commitment and assignment to a capacity feature vector. For every legal candidate matching, an edge-combination scorer fuses the selected machine and worker vectors with the known edge duration/restoration, then pools selected edges and global machine/worker context into one action logit. A masked categorical samples the *complete matching*, including WAIT. The encoder output is a learned feature, not a calibrated economic value, urgency or reservation price. There is no independent machine action; this is a structured centralized policy. A full-current-information critic supports standard PPO. Actor and critic receive no future realized events.

The proposed benefit is an inductive bias for heterogeneous service commitments: the same machine-demand computation is reused across machines, worker commitments are represented explicitly, and candidate scores depend on the machine–worker pairing rather than only a flat global vector. It may improve learning speed or selected-policy cost against a direct-health full-information PPO with the **same raw information, action mask, transition budget and nearly matched parameter count**. If not, the structural hypothesis fails at this budget. A same-architecture ablation zeroes numerical remaining-commitment fields in the actor but leaves feasibility, observed free/busy flags, critic, parameters and action set unchanged. This tests whether explicit remaining-time context contributes; the mask still reveals current feasibility, so the ablation cannot support a claim about all capacity information.

## Falsification and scope

The prelocked small pilot in `structured_demand_commitment_pilot_v3.md` trains structured S, its remaining-time ablation R, direct-health full-information G3 and always-request coordinator D3 with the same PPO transition budget and fresh training seeds. S/G3/R use identical fixed threshold submissions and matching action set; D3 differs in request history/action set and is a contextual control. Frozen V14, risk matching and rollout are evaluated on the same physical panel as strong external controls. Report H+tail cost, learning curves, availability, failures, PM/CM wait/backlog, service starts, legal WAIT, model size, environment/forecast transitions and runtime by case and training seed. A structural gain must survive a fresh physical panel and, if the locked gate passes, fresh *training* seeds. F2 is a finite-budget model-based reference, not an optimum. If S only beats D3, or fails against G3, do not claim a structural benefit. If R matches S, do not attribute any gain to remaining-time context. Any benefit over F2 cost or deployment speed requires its own same-panel evidence and disclosed planning compute.
